Checklist de seguridad

✓ OKFunciones SQL usan security definer + set search_path = public → evita hijacking de schema.
✓ OKTokens de admin validados con _exigir_permiso() antes de cualquier escritura.
✓ OKNombres sanitizados con left(trim(…), 80) y regex de palabras ofensivas.
✓ OKesc() en el cliente escapa < > " ' & en todo HTML dinámico → previene XSS.
✓ OKScores upsert: solo se guarda si el nuevo puntaje es mayor → no permite inflación desde cliente.
⚠ REVISARPuntos vienen del cliente sin validación en BD. Un usuario puede enviar puntos: 9999999 directamente vía API. Considera agregar un límite máximo en din_registrar según el tipo de juego.
⚠ REVISARRate limit no implementado en RLS/RPC. Supabase limita por IP pero no hay throttling per-usuario en din_registrar. Considera agregar un chequeo de tiempo mínimo entre registros del mismo nombre.
✓ OKClaves de admin (tokens UUID) no expuestas en JS público — se cargan sólo en páginas admin con autenticación.
✓ OKRLS de Supabase activo: anon sólo puede ejecutar RPCs listados, no acceso directo a tablas.
